# Contributing

## The one hard rule

**It must build and run on .NET Framework 4.0.** Not 4.5, not 4.8, not
.NET Core. The whole point of the project is that a machine running Windows XP
SP3 can compile and run it with nothing but the runtime installed.

That rules out, among other things:

| Not allowed | Because |
|---|---|
| `async` / `await`, `Task`-based APIs | C# 5, .NET 4.5 |
| `System.Net.WebSockets` | .NET 4.5 |
| `System.Threading.Tasks.Dataflow` | out-of-band NuGet |
| `ValueTuple`, `Span<T>`, `ArrayPool<T>` | .NET 4.5 / 4.6 |
| `nameof`, string interpolation, expression-bodied members | C# 6+ |
| `caller info` attributes | .NET 4.5 |
| Any NuGet package | there is no NuGet here, by design |

The compiler is `csc.exe` from `%WINDIR%\Microsoft.NET\Framework\v4.0.30319`,
invoked with `/langversion:4`. If it compiles, the language level is fine.

## Building

```
build.cmd            rem Release
build.cmd Debug
```

There is no `.sln` and no `.csproj` on purpose: `build.cmd` lists the source
files explicitly, which means a build needs nothing but Windows. If you add a
file, add it to `build.cmd` in the same commit.

## Testing

```
bin\Radiocity.exe selftest
```

Every signal-processing stage has a synthetic test with a numeric pass
criterion, not just "it ran without throwing". CI fails if any of them fail.

**If you change DSP code, the self-test must still pass — and if you fix a bug,
add a test that would have caught it.** The DCF77 encoder had a BCD bug that
survived because the radio test and the codec were never checked separately;
there is now a round-trip test for exactly that reason.

### What the numbers mean

| Test | Criterion | Why that number |
|---|---|---|
| AM distortion | > 90 dB below tone | below float32 resolution, so there is nothing left to measure |
| FM residual | > 50 dB below tone | discriminator noise floor |
| SSB sideband rejection | < -50 dB | a phasing receiver is judged by this and nothing else |
| Clock calibration | within 1.5 ppm | 1 ppm at 192 kHz is 0.19 Hz |
| Resampler | amplitude within 2%, > 30 dB | a bad interpolator is audible as dullness |
| DCF77 | full frame at -40 and -20 dBFS | the second one is a noisy city, not a lab |

## Style

- C# 4.0, `var` is fine, LINQ is fine (it is .NET 3.5+).
- **No heap allocation in `Process()` methods.** These run on the audio
  callback thread; an allocation there is a GC pause and an audible click.
  Preallocate in the constructor.
- Comments explain *why*, not *what*. `// add one` is noise;
  `// second 59 has no pulse, so the gap is 2 s and that is our frame sync`
  is the reason the next person will not delete it.
- Prefer a named `ReceiverOptions` field over a long positional parameter
  list. Two adjacent `double`s are a bug waiting to happen.

## Icon

`assets/radiocity.ico` is generated by `tools/make-icon.ps1`, not drawn by hand.
Change the script, run it, commit both. CI validates the ICO structure (entry
count, sizes, bit depth) but deliberately does not compare bytes, because GDI+
antialiasing differs between Windows versions.

## Commits

Present tense, one logical change: `Fix BCD packing in the DCF77 encoder`.
Not `fixed stuff` and not a 4000-line dump.
